# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Git workflow

- Commit after each meaningful, working chunk of work — don't let large amounts of uncommitted work pile up.
- Write clean, descriptive commit messages that explain *why*, not just *what*.
- Push to GitHub (`origin`) after committing, so work is backed up remotely, not just local.
- Before any destructive git operation (reset --hard, checkout that discards changes, force-push), check `git status` first and confirm with the user.
- Feature work happens on `claude/zau-region-restructure-pv5c8n`, PR'd into `main`. If that branch's PR has already merged, restart it from latest `main` before starting new work rather than stacking on merged history.
- Once a chunk of work is committed and pushed, **open the PR and merge it automatically** — don't wait for the user to say "pr n merge" each time. Still verify `mergeable_state` is clean before merging, and confirm the deploy workflow succeeds afterward, same as always.

## Project: Zau Region

A fan-made Pokémon RPG. Started as a single 1638-line HTML file; the user's stated ambition is for this to become a genuinely huge game ("hours and hours of gameplay," a project spanning weeks/months) — not a short browser-game arc. Depth over breadth: flesh out what exists before adding more.

### Direction change (2026-09-12, user) — story/cast/presentation before more districts

After Phase 14 the user laid out what "a real Pokémon game" needs beyond gym → next city → gym, in their words the reasons a game can have "hours of gameplay":
- **Characters and a full plot first.** Decide the cast *before* building more places so NPCs can be placed with real dialogue as each district is built, rather than filled in after. Main-story beats *between* gyms (not just gym-to-gym), plus side stories/side quests. The story bible (`STORY.md`/`CHARACTERS.md`) has the spine; what's missing is a beat sheet and a district-by-district cast.
- **When does Mega Evolution unlock?** Not "from the jump." The user's reference point: real games hand it over around when the team is in its thirties. Currently the Key Stone is granted on beating Dario (end of Act 1, team ~Lv.16-20) and stones are simply bought at badge tier 5 — both need re-homing into story beats. Open design question, not decided yet.
- **Presentation has to go up a level**: real screens, loading, cutscenes, interfaces, pop-ups, banners, side notes, and *animations* instead of static images — "a real real game." Cutscenes exist only as the intro's text slides (`CutsceneScene`); NPCs exist only as toast text on tiles; battles have no attack/hit/HP animations; there's no dialogue-box system, no area-name banner, no evolution/catch/Mega animation.
- Practical consequence: the next work is (1) a story + cast + Mega-unlock design pass in the bible, (2) an NPC/dialogue/cutscene engine, (3) a presentation/animation pass — and only then more districts, built with their cast and beats in hand. Retrofit the three built districts' toast-NPCs onto the real NPC system when it exists.
- **User's answers (2026-09-12)**: cast now; a full, complete story for both plot and region; Key Stone **after Badge 3 with a story-given Absol** that has "good IVs" (→ a real IV system is the honest way to deliver that, see `MEGA.md`); other stones via side quests, caves/tunnels, big story moments, some required; order = story+cast → NPC/dialogue engine (for *relevant, important* characters, not just filler) → animation pass (= the visual upgrade, one and the same).

### Visual style + future mechanic (user direction, applies to all future work)

- **Target look**: GBA/DS-era top-down JRPG, "up to Gen 5" as the explicit reference point. The current Kenney tileset is a pragmatic CC0 stand-in chosen because it's actually reachable from this sandboxed environment (flat-shaded, not true pixel-art dithering) — not a final style commitment. If a closer GBA-style CC0 pixel tileset becomes available later, swapping `public/tiles/*.png` is a contained change.
  - **Do not source actual ripped Pokémon game tile assets** (ROM-hacking/extraction resources), even if asked again — already asked and declined once (the user acknowledged the site is publicly deployed and wanted them anyway; declined because that's a categorically more direct copyright violation than the PokeAPI artwork hotlinking already in use, which is a promotional-art/established-fan-norm case, not extracted proprietary game data). The path stays: closer-styled CC0/properly-licensed tiles, or hand-drawn/commissioned art later.
- **Central battle gimmick: Mega Evolution — built (Phase 11).** The user's intended signature mechanic, now real: 6 species with real Mega forms (Gyarados, Alakazam, Gengar, Lucario, Garchomp, Absol), Key Stone from the story, one Mega Stone held item per species, once per battle. Only Gen 1-6 species ever got Megas in the real games, which is why the Gen 9 starters can't — any future Mega additions come from expanding the roster (`data/megas.js` + a stone in `data/items.js` + the base species' evolution line), never from inventing a Mega for a species that doesn't have one. The user's longer-term ambition of newer Megas from Pokémon Legends Z-A fits the same pattern once those species/lines exist.
